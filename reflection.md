# Свободная рефлексия: практика 4

Что помогло
- Минимализм и явные ограничения: стандартная библиотека, без внешних зависимостей. Это ускорило выбор решений (http.server, vanilla JS) и сняло спорные варианты.
- Единые правила (AGENTS.md): задали чёткий вектор действий и последовательность шагов. Агенты не «гуляли» — ориентировались на конкретные файлы и контракты.
- Узкоспециализированный skill (notify-mini-frontend): зафиксировал точные артефакты (http_server.py, web/*, API-роуты, Makefile serve) и критерии приёмки.
- Pre-commit: ловил хвостовые пробелы, синтаксис и падения тестов до коммита, экономя время на ревью.

Что мешало
- Пути со слэшами и пробелами: раздача статики из /web/ против корня, пробелы в системном пути macOS — требовали аккуратных кавычек и правок ссылок.
- Неочевидность табов в Makefile: одна замена пробелов на табы ломала цель — пришлось внимательно проверить отступы.
- Разные источники навыков (глобальный frontend-design vs локальный skill): легко перепутать, где хранится активный навык; понадобилась документация и перенос в .opencode.
- Перезапуск OpenCode после конфигурационных правок: неочевидный момент, без него skills/MCP не подхватываются.

Где пришлось вмешаться вручную
- Исправил пути статики в index.html (`/web/...` → `/...`), чтобы сервер корректно отдавал скрипт и стиль.
- Добавил Content-Type с charset в http_server.py для корректной раздачи CSS/JS/HTML.
- В Makefile привёл отступы к табам, добавил цель `serve`.
- В `service.py` ввёл `normalize_name`, `unsubscribe`, `list_subscribers`, и дополнил тесты.
- Для MCP сделал упрощённый stdin/stdout JSON-поток и задокументировал реальные вызовы и ошибки.

Наблюдения по инструментам
- AGENTS.md реально дисциплинирует: перед каждым значимым шагом перечитывать правила — снижает расхождения и забытые пункты.
- frontend-design хорош как методическая база, но "узкий" проектный skill критичнее: он делает результат воспроизводимым.
- MCP даже в минималистичном виде полезен, если есть чёткая документация запуска и формата запросов/ответов.
- Pre-commit должен быть быстрым: git diff --cached --check + compileall + unit tests — достаточно для учебного сервиса.

Что бы сделал иначе
- Сразу проверил бы пути статики и прописал правила подключения ассетов в skill, чтобы не ловить /web/ vs /.
- Добавил бы интеграционный тест HTTP (запуск ThreadingHTTPServer в фоне и запросы через urllib), чтобы покрыть UI/API связку.
- Оформил бы MCP в полноценный манифест и подключил через `opencode.json`, чтобы агенты могли вызывать tool напрямую.

Выводы
- Сначала контракт и проверки, потом код — это снижает регрессии и ускоряет реализацию.
- Узкие навыки под проект лучше общих: они фиксируют точные шаги, артефакты и критерии.
- Автоматические проверки перед коммитом окупаются сразу, особенно в учебных сервисах.
