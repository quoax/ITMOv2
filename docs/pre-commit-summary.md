# Pre-commit Summary

Что делает мой pre-commit
- Блокирует коммиты непосредственно в ветку `main`, требуя работать через фичевые ветки. Это снижает риск случайных пушей в основную ветку.
- Проверяет индексированные изменения на пробельные ошибки (`git diff --cached --check`): ловит хвостовые пробелы, табы в отступах и другие мелкие нарушения стиля до коммита.
- Делает быстрый синтаксический чек Python в учебном сервисе (`python3 -m compileall -q practices/practice_03/lab/demo`): гарантирует, что файлы хотя бы компилируются.
- Запускает юнит-тесты демо (`make -s -C practices/practice_03/lab test`): подтверждает, что Фича A не ломает базовое поведение.

Почему так
- Все шаги работают из коробки (git + стандартная библиотека), не требуют внешних зависимостей.
- Целенаправленно проверяем ту часть кода, где идёт активная работа (Notify Mini), чтобы быстро обнаруживать регрессии.
- Блокировка в `main` дисциплинирует процесс и снижает шанс конфликтов на ревью.

Как работает (последовательность)
1. Определяет текущую ветку и прекращает коммит, если это `main`.
2. Проверяет staged diff на пробельные ошибки; при нарушениях коммит прерывается с сообщениями от git.
3. Компилирует Python-файлы демо; при ошибке синтаксиса коммит прерывается.
4. Запускает тесты демо; при падении тестов коммит прерывается.
5. При успехе выводит `Pre-commit: OK` и пропускает коммит.

Где находится
- Локально: `.git/hooks/pre-commit` (не попадает в репозиторий при клонировании).
- Для демонстрации проверяющему: `scripts/pre-commit.sample.sh` — точная копия текущего хука.

Как проверить вручную
- Запустить образец: `bash scripts/pre-commit.sample.sh` (из корня).
- Для корректной проверки линта предварительно добавьте изменения в индекс (`git add <files>`), иначе `git diff --cached --check` ничего не найдёт.

Типичные сценарии
- Успешный коммит: все проверки проходят, виден вывод тестов и строка `Pre-commit: OK`.
- Провал по стилю: git сообщает о хвостовых пробелах/табе; исправить и закоммитить снова.
- Провал по синтаксису: `compileall` завершится ошибкой; исправить код.
- Провал по тестам: `make test` выводит падающие тесты; исправить, убедиться, что зелёные.
- Блокировка в main: хук сообщает, что коммиты в `main` запрещены; переключиться на рабочую ветку.

Обход (для диагностики)
- Разрешён только для отладки: `git commit --no-verify` пропускает хук. В обычной работе не рекомендуется.
