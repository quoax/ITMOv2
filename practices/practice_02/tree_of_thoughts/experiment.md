Файл ведёт OpenCode по вашим запросам. Агент записывает фактические результаты экспериментов и вносит изменения в связанные файлы. Свою оценку сообщайте ему в чате; вручную заполнять шаблон не нужно.

- Решение, для которого нужны альтернативы:
- Критерии выбора:
  Выбор инструмента и формата метрик для нагрузочных проверок в учебном репозитории.
  Критерии: (1) воспроизводимость без внешних зависимостей; (2) простота запуска и чтения результатов; (3) достаточность метрик (статусы, P50/P95/P99); (4) кроссплатформенность.

## Запрос

Предложи три альтернативы инструментов/подходов для нагрузочного тестирования нашего FastAPI‑эндпоинта в рамках учебного репозитория: A) hey, B) wrk со скриптом Lua, C) pytest + httpx с простым циклом и замером времени. Оцени по критериям: воспроизводимость без внешних зависимостей, простота запуска/чтения, достаточность метрик, кроссплатформенность. Выбери вариант по умолчанию и предложи краткую правку в tests_load.md.

## Варианты решения

| Альтернатива | Плюсы | Минусы | Оценка по критериям |
|---|---|---|---|
| A | hey: одна бинарь, даёт RPS и Latency Distribution, считает коды | Потребуется установка утилиты; ограниченные скрипты | 1) высокая, 2) высокая, 3) достаточна, 4) средняя |
| B | wrk + Lua: гибкость сценариев, Latency Distribution | Установка wrk и Lua‑скрипта; менее дружелюбный вывод | 1) средняя, 2) средняя, 3) высокая, 4) средняя |
| C | pytest+httpx: без внешних утилит, можно в test suite | Нет встроенной агрегации P95/P99; сложнее честно эмулировать RPS | 1) высокая, 2) средняя, 3) низкая, 4) высокая |

## Выбор

- Выбранная альтернатива:
- Почему: hey как значение по умолчанию: минимальный барьер входа, понятный summary, хватает для учебных сценариев. wrk оставляем альтернативой для продвинутых случаев. pytest‑цикл не даёт необходимых квантилей без доп. кода.
- Как проверим: make step2 продолжает проходить; инструкции в tests_load.md используют hey и, опционально, wrk.
