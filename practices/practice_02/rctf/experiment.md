# R.C.T.F.

Файл ведёт OpenCode по вашим запросам. Агент записывает фактические результаты экспериментов и вносит изменения в связанные файлы. Свою оценку сообщайте ему в чате; вручную заполнять шаблон не нужно.

- **Role:** Инженер производительности, настраивающий воспроизводимые нагрузочные сценарии для учебного FastAPI‑сервиса
- **Context:** Сервис POST /api/reviews; вход ReviewRequest {diff:string}; статусы: 2xx при успехе, 422 при нарушении схемы, 502 при сбое LLM; нагрузочное тестирование проводится с мок‑LLM без jq и внешних скриптов
- **Task:** Уточнить формат фиксации результатов нагрузочных сценариев в tests_load.md: какие поля обязательно фиксировать после прогона и как их получить стандартными инструментами
- **Format:** Маркированный список полей с краткими пояснениями и примерами команд hey/wrk для извлечения значений

## Полный запрос

Собери формат фиксации результатов для каждого нагрузочного сценария из tests_load.md. Роль: инженер производительности. Контекст: FastAPI POST /api/reviews, статусы 2xx/422/502 как описано; используем мок‑LLM; инструменты hey или wrk. Задача: предложить единый шаблон «Что сохраняем после прогона», минимум: дата/время, инструмент и версия, входная нагрузка (rps, длительность, concurrency), итоговые статусы (распределение по классам 2xx/4xx/5xx), latency P50/P95/P99, error rate, заметки. Формат: маркированный список с мини‑примером команд, как извлечь цифры без jq.

## Что получили

Предложенный шаблон фиксации результатов:

- Дата и время запуска (UTC или локальное): например, `2026-09-20T12:34:56`.
- Инструмент и версия: `hey v0.1.4` или `wrk 4.2.0`.
- Параметры нагрузки: RPS/Concurrency и длительность. Пример: `-q 10 -z 60s` (hey) или `-t2 -c20 -d60s` (wrk).
- Итоговые статусы в процентах: доли 2xx/4xx/5xx. В hey читаются из summary; в wrk — из секции Requests/sec и non‑2xx/5xx.
- Latency: P50/P95/P99, выводятся обоими инструментами в summary.
- Error rate: 1 - (2xx/all). В hey виден как non‑2xx count; в wrk — через non‑2xx/5xx.
- Заметки: конфигурация мока LLM (включён/таймаут), машина, фоновые нагрузки.

Мини‑пример фиксации (hey):

```
hey -z 60s -q 10 -m POST -H 'Content-Type: application/json' -d '{"diff":"x"}' http://localhost:8000/api/reviews
# Скопировать блок Summary: Latency (P50/P95/P99) и статус‑коды (2xx/4xx/5xx), записать значения в раздел сценария.
```

Мини‑пример фиксации (wrk):

```
wrk -t2 -c20 -d60s -s scripts/review_valid.lua http://localhost:8000
# Из вывода: Latency Distribution (50/95/99%) и Non‑2xx or 3xx (как индикатор ошибок), Requests/sec.
```
