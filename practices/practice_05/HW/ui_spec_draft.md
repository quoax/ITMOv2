# UI Спецификация: Пагинация и серверная сортировка списка подписчиков

## Область действия
Экран списка подписчиков в веб‑приложении. Реализуется серверная пагинация и выбор направления сортировки. Ключ сортировки фиксирован на стороне сервера; клиент выбирает только направление `asc|desc` согласно конституции.

## Термины
- Страница — подмножество элементов, определяемое `offset` и `limit`.
- Текущее состояние — комбинация параметров `{ offset, limit, sort }`.
- total — общее число элементов на сервере после фильтров, без пагинации.

## Компоненты UI

### Таблица списка
- Назначение: отобразить `items` из ответа сервера.
- Структура:
  - Заголовок таблицы с названиями столбцов (без сортируемых контролов на уровне колонок).
  - Тело с строками подписчиков.
  - Футер/подвал не обязателен; сводка отображается в пейджере.
- Сводка под таблицей: текст "Показано X–Y из Z", где:
  - X = `offset + 1` при `total > 0`, иначе 0
  - Y = `offset + items.length`
  - Z = `total`

### Пейджер
- Элементы:
  - Кнопка "Первая" (|<)
  - Кнопка "Предыдущая" (<)
  - Нумерация страниц с окном видимости (например, 5 ближайших): 1 … N
  - Кнопка "Следующая" (>)
  - Кнопка "Последняя" (>|)
- Состояния кнопок:
  - "Первая"/"Предыдущая" disabled при `offset == 0` или при загрузке.
  - "Следующая"/"Последняя" disabled при `offset + limit >= total` или при загрузке.
  - Номер текущей страницы выделен.
- Отображение страниц:
  - `currentPage = floor(offset / limit) + 1`
  - `pageCount = ceil(total / limit)` при `total > 0`, иначе 1
  - Для больших `pageCount` используется усеченное окно и многоточия.

### Селектор сортировки
- Контрол: селектор направления сортировки (radio/select/toggle):
  - Значения: "По возрастанию" → `sort=asc`, "По убыванию" → `sort=desc`.
- Описание: применяется к серверному ключу сортировки (фиксирован на сервере; стабильная сортировка, при равенстве — по первичному ключу `id asc`).
- Поведение: смена значения сбрасывает `offset` в 0.

### Лоадеры и блокировки
- Глобальный/локальный индикатор загрузки на время запроса списка.
- На время запроса:
  - Пейджер и селектор сортировки находятся в состоянии disabled (MUST).
  - Повторные действия пользователя инициируют отмену текущего запроса и запуск нового (SHOULD, через AbortController).

### Сообщения состояния
- Пустой список: блок "Список пуст" с коротким пояснением и кнопкой "Обновить" (повтор запроса).
- Ошибки: см. раздел "Обработка ошибок".

## Пользовательские действия и поведение

### Навигация по страницам
- Клик "Первая": `offset = 0`, выполнить запрос.
- Клик "Предыдущая": `offset = max(offset - limit, 0)`, запрос.
- Клик по номеру страницы P: `offset = (P - 1) * limit`, запрос.
- Клик "Следующая": `offset = offset + limit`, запрос.
- Клик "Последняя": `offset = (pageCount - 1) * limit`, запрос.
- При каждом действии обновляется URL (query‑параметры) и история (SHOULD).

### Смена сортировки
- Выбор asc/desc:
  - Устанавливает `sort` соответствующим значением.
  - Сбрасывает `offset = 0`.
  - Выполняет запрос с новыми параметрами.

### Обновление/повтор запроса
- Кнопка "Обновить" на пустом/ошибочном состоянии инициирует повторный запрос с текущими параметрами.

## Состояния интерфейса

### Initial/loading
- При первичной загрузке параметры берутся из URL (если присутствуют), иначе:
  - `offset = 0`, `limit = 20`, `sort = asc` (defaults).
- Отображается лоадер, контролы заблокированы.

### Success
- Таблица показывает `items`.
- Пейджер отображает текущую страницу и доступность навигации, основанные на `total`.
- Сводка X–Y из Z согласована с фактическими `items` и `total` (MUST).

### Empty
- При `total == 0` и `items.length == 0`:
  - Показывается пустое состояние.
  - Пейджер скрыт или disabled.
  - Сводка "Показано 0 из 0".

### Edge: несогласованный offset
- Если `items.length == 0`, `total > 0`, `offset > 0` (например, данные сократились):
  - SHOULD: автоматически перейти на последнюю валидную страницу:
    - Вычислить `pageCount = ceil(total / limit)`
    - Новый `offset = max((pageCount - 1) * limit, 0)`
    - Обновить URL и повторить запрос.
  - На время корректировки — краткий лоадер.

## Обработка ошибок

### Формат ошибок
- Ожидается единый формат:
  ```
  { "error": { "code": "...", "message": "...", "details": { ... } } }
  ```
- MUST: не показывать внутренние детали; использовать `message` для пользователя.

### Категории
- 400 Bad Request (валидация параметров):
  - Отображается inline‑сообщение над таблицей: "Некорректные параметры запроса".
  - SHOULD: подсветить проблемные параметры (например, `limit`, `sort`), отобразить `details` если доступны читабельно.
  - SHOULD: локально санитизировать значения и предложить "Применить исправления":
    - `limit` → в [1, 100] (клиппинг)
    - `offset` ≥ 0
    - `sort` ∈ {asc, desc}
  - После подтверждения — перезапрос с исправленными параметрами.
- 5xx / сеть:
  - Показывается уведомление/баннер: "Ошибка сервера. Попробуйте повторить."
  - Опции: "Повторить" (повтор запроса), "Отмена".
  - Контролы разблокируются после завершения запроса; при повторе — снова блокируются.
- Отмена (Abort):
  - Не считается ошибкой; UI без сообщений, переходит к состоянию нового запроса.

## URL и контракт API

### Query‑параметры (SHOULD сохраняться и восстанавливаться)
- `offset`: целое, `default=0`, `min=0`.
- `limit`: целое, `default=20`, `min=1`, `max=100`.
- `sort`: строка, `asc|desc`, `default=asc`.
- При изменении параметров UI выполняет `history.pushState`/`replaceState` для отражения состояния.

### Восстановление состояния
- При монтировании:
  - Парсинг URL → валидация/санитизация → применение.
  - Невалидные значения исправляются к ближайшим допустимым и записываются обратно через `replaceState` (SHOULD).

### Запрос
- Метод: GET `/api/v1/subscribers?offset={offset}&limit={limit}&sort={sort}`
- Ответ 200:
  ```
  { "items": [...], "total": <number> }
  ```
- Клиент MUST доверять `total` и вычислять доступность навигации локально.

## Нефункциональные инварианты (Frontend)
- MUST: на время любых сетевых запросов блокировать пейджер и селектор сортировки.
- MUST: показывать визуальный индикатор загрузки.
- SHOULD: отменять предыдущие незавершенные запросы при новых действиях (AbortController).
- MUST: не превышать `limit > 100`; UI предотвращает ввод/выбор большего значения.
- MUST: вычисление страниц и доступности кнопок основывается на `total`, а не на длине `items`.

## Тексты и локализация
- Основные метки:
  - Пейджер: "Первая", "Предыдущая", "Следующая", "Последняя".
  - Сортировка: "По возрастанию", "По убыванию".
  - Сводка: "Показано X–Y из Z".
  - Пустой список: "Список пуст".
  - Ошибки: 400 — "Некорректные параметры запроса"; 5xx — "Ошибка сервера. Попробуйте повторить."

## Открытые вопросы
- Ключ сортировки на сервере: какой именно используется по умолчанию (например, дата подписки или id)? UI предполагает фиксированный ключ, выбирается только направление.
- Нужен ли селектор `limit` для пользователя? В текущем объеме — отсутствует; при добавлении необходимо синхронизировать `limit` в URL и соблюдать max=100.
