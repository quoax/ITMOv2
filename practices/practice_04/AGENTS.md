# План для рабочих агентов: Practice 03 → фронтенд фичи A и B

Цель: реализовать легкий фронтенд над учебным сервисом подписок из `practices/practice_03/lab/demo`, сохраняя ограничение на стандартную библиотеку Python и минимальные изменения. Фича B является продолжением фичи A.

## Текущее состояние кода (practice_03)
- Бэкенд: `service.py` хранит подписчиков в памяти процесса (`subscribers = set()`), реализована функция `subscribe(name)` с проверкой пустой строки.
- Тесты: `test_service.py` покрывают добавление, пустое имя и отсутствие дублей.
- Документация: `demo/README.md` описывает поведение и запуск тестов через `make test`.
- Инфраструктура: внешних зависимостей нет, используется Python 3.10+, стандартная библиотека.
- Отсутствует HTTP-слой и фронтенд.

## Фичи для реализации

Фича A: минимальная веб-страница управления подписками
- Задачи:
  - Добавить простой HTTP-сервер на стандартной библиотеке (например, `http.server`/`BaseHTTPRequestHandler`) с JSON API, переиспользующий `service.py`.
  - Создать статическую страницу `web/index.html` и `web/script.js` + `web/style.css` для:
    - Добавления подписчика по имени
    - Просмотра списка текущих подписчиков
    - Удаления подписчика (потребует поддержки на бэкенде)
  - Ввести единую нормализацию имени (`normalize_name(name)`) и использовать её в API и в `service.py`.
- API спецификация (стандартная библиотека, JSON):
  - `GET /api/subscribers` → `{ subscribers: ["Ann", "Bob", ...] }`
  - `POST /api/subscribe` (body: `{ "name": "Ann" }`) → `{ subscribed: true }` или ошибка 400 при пустом имени
  - `POST /api/unsubscribe` (body: `{ "name": "Ann" }`) → `{ unsubscribed: true|false }`
  - `GET /` → отдать `web/index.html`, статику из `web/`
- Критерии готовности:
  - Ручной сценарий: страница загружается, можно добавлять/удалять, список обновляется без перезагрузки (через fetch).
  - Юнит-тесты для `unsubscribe` и нормализации имён.

Фича B: персистентность и улучшения UX (продолжение A)
- Задачи:
  - Персистентность набора подписчиков в `subscribers.json` (JSON) — `save_state()` после успешных операций и `load_state()` при старте сервера/импорте.
  - Устойчивость к отсутствию/повреждению файла (восстановление пустого множества, без падения).
  - Дополнения UI:
    - Индикация статуса операций (успех/ошибка), подтверждение перед удалением
    - Поиск/фильтр по списку (клиентская фильтрация с debounce)
    - Импорт/экспорт состояния (скачивание и загрузка JSON)
- Критерии готовности:
  - После рестарта процесса состояние подписок сохраняется.
  - Импорт/экспорт корректно работает в браузере.
  - Интеграционный тест персистентности проходит.

## Риски и проверки
- Корректная нормализация имён: выбранный подход (`casefold`) может менять семантику некоторых языков; при необходимости оставить только `strip()`.
- Гонки при одновременных HTTP-запросах: для учебного сервиса допустимо отсутствие блокировок; иначе — `threading.Lock` вокруг `subscribers` и операций сохранения.
- Повреждение `subscribers.json`: восстановление пустого состояния, логирование в stdout.
- Порты и CORS: сервер и статика с одного источника, CORS не требуется.

## Критерии приемки (E2E)
1. Пользователь открывает страницу, видит пустой список, добавляет "Ann" — список обновляется.
2. Повторное добавление "Ann" не создаёт дублей.
3. Удаление "Ann" возвращает `{ unsubscribed: true }`, элемент исчезает из списка.
4. После перезапуска процесса сохранённые подписки восстанавливаются.
5. Импорт/экспорт JSON работают, фильтр по списку работает, статус операций понятен.
