## Эталоны (по demo/)

1. Как запустить тесты? Укажи файл-источник.
   - Ответ: командой `make test`, которая запускает `python3 -m unittest -v`.
   - Основание: demo/Makefile (target test) и README.md ("Проверка: make test.").

2. Что будет при пустом имени подписчика? Подтверди кодом.
   - Ответ: будет выброшено исключение ValueError("empty name").
   - Основание: demo/service.py (if not name.strip(): raise ValueError("empty name")), тест demo/test_service.py::test_empty.

3. Где реализован unsubscribe? Проверь предпосылку вопроса.
   - Ответ: функция unsubscribe в репозитории не реализована/отсутствует.
   - Основание: в demo/ нет функции unsubscribe (ни в service.py, ни в тестах/README).

4. Какая CI-система запускает тесты? Если сведений нет, скажи об этом.
   - Ответ: сведений о CI нет в предоставленных материалах.
   - Основание: нет конфигураций CI (нет .github/workflows, GitLab CI, Jenkinsfile и т.п.), README не указывает CI.

5. Сохраняются ли подписки после перезапуска процесса? Подтверди кодом.
   - Ответ: не сохраняются; подписчики хранятся в памяти процесса.
   - Основание: demo/README.md ("Подписчики хранятся в памяти процесса."), структура: `subscribers = set()` в service.py без персистентности.

## Обоснование выбора

- База qwen2.5-coder:7b и квантизация Q4_K_M выбраны для запуска на локальном железе (Apple M4, 16 GB RAM) с приемлемым потреблением памяти и скоростью декодирования.
- Для itmo-chat установлен num_ctx=4096 как компромисс между устойчивостью и памятью; для itmo-agent — 65536 для сценариев с длинным контекстом и задач чтения в read-only агенте.
- Системный промпт в itmo-chat нужен для строгих ответов «по фактам»; отсутствие системного промпта в itmo-agent позволяет сравнить влияние system.txt.
